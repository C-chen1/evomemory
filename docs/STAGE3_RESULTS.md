## 2. 被实验否定或必须修正的结论

### 2.1 预算预留高估 34 倍（已修）

旧公式 `max_tokens + text_bytes + 4 × 图片字节数`：一张 15 KB 面板预留 **71,208** token，
而同一类调用的实测用量是 **2,099**。一次图像调用就吃掉 1M 预算的 7%（按估算）。
一个实验会在真实花费远未到线时就被自己的估算锁死。

修正为 `max_tokens + text_bytes//3 + 4000×图片数 + 2048`（约实测量的 2-3 倍）。

### 2.2 训练面板的标签是"定义性的"，不是"学到的"

`expected_action` 由任务生成器按隐藏规则直接算出，与模型在训练面板上做了什么无关。
因此**跑训练面板无法把阈值变得可确定**，只是花 token 把已知的事再观察一遍。

`panel-v4` 因此改为 **oracle 上界实验**（已知正确规则能带来多少提升），
而不是"学习"实验。协议修订二记录了这次改动，发生在任何测试面板运行之前。
省下约 130 次调用。

### 2.3 视觉任务已经没有提升空间（天花板效应）——本阶段最重要的负面结果

`panel-v4` 的 V1 臂（**有图、无记忆**）在跑完的 2 个未见面板上**全部成功**：

```
test-000: A(red,58)→leave_off  C(red,11)→activate     全对
test-001: A(red,16)→activate   B(red,93)→leave_off    全对
test-002: 空响应中断（未行动）
```

模型自己从任务文字 "Switch ON red-lamp zones **where operating restrictions permit**"
加上可见的读数，推出了"读数高 = 受限制"。**不需要记忆**。

这说明 `panel` 系列任务在两个方向上都不成立：

| 版本 | 任务文字 | 结果 |
|---|---|---|
| panel-v2 | "打开所有红灯区" | 与隐藏判分规则**冲突**；模型遵守文字 → 必然失败。记忆臂看似有效，其实是在抵消一个自相矛盾的指令 |
| panel-v3/v4 | "在运行限制允许的范围内打开红灯区" | 冲突消失，但**限制条件可从文字+像素推出** → 无记忆也能全对，记忆没有发挥空间 |

**结论：在当前的观测接口下，这个任务无法同时做到"可解"和"不可推断"。**
要留下提升空间，限制必须依赖**当前像素里看不到的历史事实**（例如"此前已被确认过两次的区域不得再次激活"），
而不是从当前面板就能算出来的读数阈值。

这解释了此前所有视觉实验的怪异之处：V2-threshold 的 4/4 不是记忆的功劳，
而是任务恰好把答案放在了文字里；那次 V1 中断反而掩盖了这一点。

## 3. 实验状态（严格区分）

| 实验 | 状态 |
|---|---|
| 归因式演化（离线脚本） | ✅ 完整，机制成立（2/8 → 5/8） |
| 归因式演化（真实模型） | ⚠️ 历史结果 2/8 → 5/8 来自已被停用的旧逻辑，**需用新归因重跑** |
| panel-v4 V1 | ⚠️ 2/4 完成、1 空响应中断、1 未跑 → 按预注册判为**实验未完成** |
| panel-v4 V2T | ⛔ **主动不跑**：V1 已在跑完的面板上达到上限，配对比较不可能有信息量 |
| G 臂（结构化 + 门，无 critique） | ⛔ 未跑 |
| 视觉记忆的真正增益 | ❌ **当前任务设计无法测量**，原因见 §2.3 |

### 3.1 为什么主动停掉 V2T

预注册写的是"任一臂未跑完 4 个面板 → 实验未完成"。V1 已完成 2 个且全对。
在 V1 已经 100% 的情况下，再花约 68 次调用跑 V2T 只能得到"也是 100%"，
无法区分记忆的作用。继续投入预算去确认一个天花板，不如把结论写清楚。
