## 1. 为什么需要一个专门的视觉环境

上一阶段的多模态部分只有基础设施：内容寻址的图片存储、缩略图、caption。没有任务，
因此"多模态是否有用"这个问题从未被检验，`C` 模式在没有图像的 benchmark 上退化成 `B`。

要检验它，必须有一个**必须看图才能做对**的任务。这带来一个硬要求：
**环境不能通过任何文本渠道泄漏图像里的状态**，否则模型可以绕开视觉完成任务，
实验测到的就是语言能力而不是视觉记忆。

## 2. 任务

控制面板，每个 zone 有一盏灯（green / amber / red）、一个两位数读数、一个开关。

- **任务**：把灯是红色的 zone 的开关打开。
- **隐藏规则（lockdown）**：红灯**且**读数 ≥ 50 的 zone 不能动。

灯色与读数**只存在于像素里**。这是一个合取，且两个操作数都是视觉事实——
它同时检验了 P1 的结构化条件（合取）与 P3 的视觉证据。

---

## 3. 泄漏防护（每条都有测试）

| 渠道 | 处置 | 测试 |
|---|---|---|
| 任务文本 | 只陈述可观测判据"红灯"，不出现读数、不出现 `lockdown`、不出现阈值 50 | `test_goal_text_leaks_neither_values_nor_the_hidden_rule` |
| 工具输出 | `list_zones` 只返回 zone 名字，**没有任何工具能查灯色或读数** | `test_list_zones_hides_state`、`test_no_tool_can_reveal_state` |
| 图片元数据 | PNG 不写 `Description` / caption | `test_image_carries_no_caption_metadata` |
| 文件名 | 内容寻址（sha256），名字里没有语义 | `EvidenceStore._path_for` |
| 判分 | 对照生成时算出的真值，不读模型自述 | `verify()` 只比较 `env.switches` |

还有一条反向测试：**如果去掉图像，任务必须做不出来。**
`vision_experiment.py --dry-run` 里 V0 的替身是"盲"的，结果 0/4，V1 为 4/4。
这并不是视觉能力的证据（替身读的是真值），而是证明**环境没有文本后门**。

## 4. 证据组织

```
原始面板 PNG  ──► Evidence(kind=IMAGE, sha256=…)
                      │
                      ├──► 每个任务都入库一次（即使失败），原始字节不可变
                      │
                      └──► 经验只引用 evidence_id，不复制像素
```

与上一阶段一致：原图永不覆盖，任何派生表示（缩略图、caption）都是独立行 + `derived_from`。
视觉事实（灯色、读数）由模型在推理中读出，**不作为可信数据**——判分时用的是生成时的真值。

## 5. 四个实验臂

| 臂 | 是否发送图像 | 记忆 | 用途 |
|---|---|---|---|
| V0 | ✗ | 无 | 下界：证明任务需要视觉 |
| V1 | ✓ | 无 | 视觉本身的能力 |
| V2 | ✓ | 散文经验 | 视觉 + 文本记忆 |
| V3 | ✓ | 可执行条件 | 视觉 + 结构化记忆（合取由代码判定） |

V1 vs V0 回答 H3 的前半（视觉是否必要）；V2/V3 vs V1 回答后半（跨任务视觉经验是否可复用）。

## 6. 诚实的边界

1. **没有 live 数据。** 任何"多模态记忆提升了 X%"的说法都是伪造的。
2. **"能读图" ≠ "长期视觉记忆有用"。** 即使 V1 远高于 V0，也只说明模型会看图；
   V2/V3 相对 V1 的增量才是记忆的贡献。
3. **没有实现原生跨模态向量检索。** 检索走的是文本索引（经验文本 + caption），
   原始图像在注入时作为附带证据发送。准确的说法是"文本索引辅助的视觉证据复用"。
4. **面板是合成的。** 真实截图有噪声、遮挡、分辨率变化，本环境都没有。

## 8. 预期与反预期

值得记录的两种情况，都必须原样报告：

- 若 **V1 ≈ V0**：说明这个模型在这个面板上读不出状态。此时该做的是换更强的模型或更清晰的面板，
  而不是继续加记忆。
- 若 **V2 ≈ V1**：说明"看过一张面板"没有迁移价值。这与文本侧的结果（S ≈ B）一致，
  会进一步支持"当前瓶颈不在记忆表示"这一判断。

真正能支持 H3 的证据是 **V2 或 V3 显著高于 V1**，且 V1 显著高于 V0。

## 9. 实测结果（2026-11-21，`live_model`）

模型 `deepseek-flash`，8 个程序化面板，`scripts/vision_experiment.py`。
原始记录：`artifacts/vision/`、`artifacts/vision_v0/`、`artifacts/vision_v2/`。

| 臂 | 成功率 | targets 通过 | lockdown 通过 | 附带动作 | 日志 | 发送图像 |
|---|---|---|---|---|---|---|
| **V0 无图** | 0/8 | **0/8** | 8/8 | 8/8 | 8/8 | 0 |
| **V1 有图** | 0/8 | **8/8** | **0/8** | 8/8 | 8/8 | 8 |
| **V2 有图 + 失败驱动记忆** | 0/8 | 8/8 | **0/8** | 8/8 | 8/8 | 8 |

### 9.1 V0 与 V1 的失败是互补的

- **V0 一个目标都没做**（targets 0/8）：没有图像，它无法知道哪些 zone 是红的，于是不动手。
- **V1 目标全做对**（targets 8/8），但**lockdown 全部违反**（0/8）：它准确读出了灯色和读数
  （调试记录里模型报出 `A red 35, B red 56, C green 85`，与真值完全一致），
  于是按"红灯就打开"执行——把 lockdown 区也打开了。

这说明：**视觉感知不是瓶颈，缺失的是规则**。这正是记忆应该补的那一环。
这也是第一次用数据把"感知"与"记忆"两个失败源分离开。

### 9.2 V2 学到的规则是错的（本阶段最重要的发现）

V2 在失败后用图像 + 评分器反馈向模型询问规则，共学到 4 条，其中：

> "Only switch ON zones whose lamp is red … do not touch a zone whose lamp is **amber**(C),
> since an **amber lamp marks a locked-down zone** that must be left alone."

**真相是"红灯且读数 ≥ 50"，模型却把它归因成"琥珀灯"。** 这条错误规则被注入后续任务，
既不阻止它打开真正的 lockdown 区（红灯），又可能让它漏掉合法的目标。

结果：V2 与 V1 成功率相同（都是 0/8），但失败原因变了——
从"不知道规则"变成"学错规则"，并且错误规则在任务之间传播。

对照第一次运行（提取预算不足、只学到部分规则时）lockdown 曾达到 2/8，
修好提取预算后反而回到 0/8：**更多学习 = 更系统地学错**。

### 9.3 这条结果支持什么、不支持什么

**支持**：
- 视觉链路（图像输入、程序化判分、证据入库）在真实模型上可用。
- 环境没有文本后门：V0 与 V1 的 check 分布完全互补。
- **程序化校验挡不住语义错误的经验**——这条在文本任务上提出过，现在在视觉任务上复现了。

**不支持**：
- H3（跨任务复用视觉证据能提升成功率）：**未获支持**。V2 = V1 = 0/8。
- "模型能看图"≠"视觉记忆有用"。前者成立，后者在这一轮被证伪。

### 9.4 下一步该怎么做（由这条结果直接推出）

1. **失败归因需要程序化的操作数**，不能只让模型自由叙述。可用做法：评分器在报错时给出
   违规记录的**视觉事实**（灯色、读数），让提炼器从"这些事实的组合"里推断条件，
   而不是让模型凭印象写一句话——这与文本侧 `from_counterexamples` 是同一个思路。
2. 提炼出的规则必须**先在历史任务上回放验证**（能区分开那些被违反的与未被违反的），
   通过后才注入。当前 V2 没有任何回放验证，这是它系统性学错的直接原因。
3. 在这两条落地之前，视觉记忆不应作为对外结论。
