# EvoMemory 技术报告（面试视角）

> 2026-11-21 复核：历史演化实验的匹配式 strike 不能证明规则造成跳过；不要把该实验表述为已验证的精确因果归因。详见 `FAILURE_ANALYSIS.md`。

面向技术负责人与 AI 应用开发面试官。所有数字可用 `artifacts/` 下的数据重算，
每条结论标注了证据强度。

---

## 1. 项目解决的真实问题

Agent 做完一个任务就忘掉一切。同一个业务规则，今天踩坑、明天还踩；
同一个错误，换个任务重来一遍。把经验存下来并不难，难的是三件事：

1. **存什么**——一次成功可能是运气，一次失败可能是环境问题，盲目"记住一切"会让记忆库迅速变成噪声；
2. **怎么信**——模型自己说"这条经验是对的"没有任何约束力；
3. **什么时候能用**——经验是在 A 情境下学到的，B 情境下照搬就是负迁移。

EvoMemory 就是围绕这三件事做的一个可运行系统 + 一套可复现的验证方法。

---

## 2. 为什么自然语言记忆会出问题

这不是理论担忧，是实测出来的。

**现象**：任务规则是"排除同时满足 `tier=gold` **且** `note=audit` 的记录"。
模型写下的经验是 *"exclude records with tier=gold and note=audit"*。
下一个任务里，它把这条读成"排除 gold **或** audit"，把只满足一半条件的记录也跳过了，
结果是**少做了本应做的操作**（`targets_actioned: 3/4`，直接可观测）。

连接词在文本里只占一个词，但决定了规则的对错。这暴露了两个独立缺陷：

| 缺陷 | 表现 | 修法 |
|---|---|---|
| 经验丢操作数 | 模型写"检查例外标记"，不说哪些标记 | `_cites_operand`：不含判别性取值的经验回落到确定性提取器 |
| 经验丢逻辑结构 | "且"被读成"或" | 结构化谓词：把连接词变成数据，由代码求值 |

**第二个缺陷的归因后来被实验修正了**——补上操作数之后，散文模式自己能解对合取。
这说明主要问题是操作数缺失，不是散文无法表达连接词。原判断有误，已写入 `FAILURE_ANALYSIS.md`。

## 3. 结构化双表示的设计

每条经验同时有两种表示：

```json
{
  "lesson": "同时满足两个条件时跳过该记录",
  "condition": {"all_of": [
    {"field": "tier", "op": "eq", "value": "gold"},
    {"field": "note", "op": "eq", "value": "audit"}
  ]}
}
```

散文给模型理解与迁移，谓词给代码执行。冲突时以谓词为准，并留痕。

**核心算法是从反例结构推断连接词**：

| 证据 | 推断 |
|---|---|
| 一条记录同时携带两个属性 | 合取（它同时具备两项才被排除） |
| 多条记录各携带不同的单属性 | 析取（任一项单独就足够） |
| 多条记录携带相同的单属性 | 单个叶子 |

这一步之所以重要：从一句话里无法可靠判断"且"还是"或"，但**从反例的分组结构里可以**。

工程约束（每条都有测试）：三值逻辑（`UNKNOWN` ≠ `FALSE`）、深度/节点/字段白名单限制、
禁止 `eval`、`Tri.__bool__` 直接抛错（从语言层面禁止 `if tri:`）。

## 4. Harness 如何控制记忆生命周期

```
任务执行 → 轨迹 → 程序化验收(verified_by=program)
   → 候选经验 → 9 项程序化校验 → accepted → active
   → 检索(按 family 过滤) → 判定 → 注入 → 行动
```

权限是代码强制的，不是文档约定：

| 动作 | 谁能做 | 越权的后果 |
|---|---|---|
| 创建候选经验 | 提取器 | 模型自评成功 → 直接不提取 |
| 接受/拒绝 | 校验器 | 模型调用被拒（`MemoryWriteError`） |
| 激活 | Gate | 同上 |
| 声明任务成功 | **没有任何模型** | 只有 `bench.verify()` 的程序比对 |

经验按 `(experience_id, version)` 不可变存行，修订产生新版本，旧版本永久可读。
证据内容寻址（sha256），原图永不覆盖，派生表示带 `derived_from` 血缘。

## 5. 多模态记忆保存了什么额外信息

- **原始面板图像**以内容寻址存储，判分用生成时算出的真值，不读模型自述。
- 视觉事实（灯色、读数）**只存在于像素**：没有任何工具能查询它们，
  任务文本不含读数，图片不含 caption 元数据。这三条各有一个测试。
- 反向验证：盲的 agent 在该环境上得 0 分——说明环境没有文本后门。

**状态**：链路实现 + 离线测试通过；**live 实验未运行**（预算耗尽）。
任何"多模态提升了 X%"的说法目前都不成立。

## 6. 经验演化有没有提升成功率（这是最该被追问的一条）

**答案：没有。而且这一点是本项目最有价值的发现之一。**

| 对照 | 结果 | 检验 |
|---|---|---|
| 无记忆 → 简单文本记忆 | 0/8 → 6/8 | McNemar p=0.031 |
| 简单文本记忆 → 结构化记忆 | 6/8 → 6/8 | p=1.0，且结构化多花 43% token |
| 完整生命周期 → 简单记忆（18 任务） | 10/18 vs 11/18 | p=1.0，完整链路多花 19% token |

把 token 拆开看原因：完整生命周期在 18 个任务里发起了 **38 次 critique 调用，其中 35 次判定是 apply 或 adapt**——
等于花模型调用去确认确定性检查已经知道的事。

据此实现了**条件化 critique**：只在结构性检查无法定案时（无条件 / 无 scope / 含否定）才咨询模型。
实测在 5 个任务上把 critique 调用降到 **0**，成功率未下降。

## 7. 哪些实验支持结论，哪些推翻了假设

**支持的**：
- 记忆对真实模型有大幅提升（0% → 75%，配对检验 p=0.031），且这个数字来自真实计费、程序判分。
- 检索必须按 family 过滤（曾经因为没做，导致某 family 全程零记忆，作废 658 次调用）。

**推翻的**：
- **H1（结构化提升复杂逻辑任务）**：未获支持。S 与 B 完全打平，成本更高。
- **H2 的前提**：critique 的价值被高估——35/36 次判定没有改变决策。
- **我自己关于 F1 的归因**：原以为是"散文表达不了合取"，实测是"经验没写操作数"。

**仍未知**：
- H3（视觉记忆）、H4（校验门）无数据。
- E 只跑了 5 个任务，无法判断"跳过 critique 是否无损"。

## 8. 当前局限（主动说，不等被问）

1. n 小。8-18 个任务、2-3 个规则模板，有效样本量接近模板数而非任务数。
2. 任务是人造的记录表操作，不能外推到真实业务。
3. 没有自动化泄漏检查，靠"一次 run 一个库"的结构保证。
4. 没有过期/冲突规则的任务，因此校验门的价值无法被测出。
5. 结构化 vs 散文的对照与 prompt 变更混杂，无法完全归因。
6. 视觉实验未运行。

## 9. 我独立实现了什么

全部代码自写，未复制任何参考仓库（其中 CMA-Harness 无许可证，明确禁止复用）。

| 模块 | 内容 |
|---|---|
| `predicate.py` | 三值谓词引擎：合取/析取/否定/比较/存在，深度与规模限制，无反例连接词推断 |
| `memory.py` + `db.py` | 版本化经验库、7 状态机、6 类写入者权限、追加式事件日志、schema 迁移 |
| `evidence.py` | 内容寻址证据存储、`derived_from` 派生血缘 |
| `harness.py` | Memory Gate、token 预算上下文、Trace、Replay、Recovery、可执行规则工具、断点续跑 |
| `lifecycle.py` | 提取（模型 + 确定性双路）、9 项校验、条件化 critique、重建 |
| `retrieval.py` | BM25 + 哈希向量 + RRF，确定性 tie-break |
| `bench.py` / `visual_bench.py` | 两个程序化判分基准（文本 / 视觉），含泄漏防护 |
| `metrics.py` | 配对 McNemar、bootstrap CI、按族聚类、有效独立性、MDE |
| `multimodal.py` | 缩略图保真度实测、压缩成本表 |
| 测试 | **166 个**，覆盖范围含对抗输入、等价穷举、确定性、预算、权限 |
